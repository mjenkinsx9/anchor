# Anchor v0.2.0 — Formal Claude Code Plugin

**Date:** 2026-06-10
**Status:** Approved design
**Supersedes:** the installation/distribution sections (§3 install, §12 distribution) of `2026-06-09-anchor-design.md`. All review/init/CLI behavior from v0.1.0 is unchanged unless stated here.

## 1. Goal

Convert Anchor from a symlink-installed personal tool into a formal Claude Code
plugin so it installs on any of the user's machines with two commands and
updates with one. Single-user, multi-machine. The anchor repo goes public on
GitHub; a separate personal marketplace repo catalogs it.

**Non-goals:** multi-user support guarantees, CI/CD, npm publishing, backward
compatibility with the symlink install (it is removed, not maintained).

## 2. Decisions (from brainstorming)

| Question | Decision |
|---|---|
| Scope | Multiple machines, single user |
| Hosting | `anchor` repo public on GitHub |
| CLI packaging | Single-file esbuild bundle committed to the repo |
| Existing symlink install | Fully migrated to plugin; no dual mode |
| Marketplace | Separate personal marketplace repo listing anchor |
| Restructure approach | In-place: the anchor repo IS the plugin |

The GitHub account is the user's authenticated `gh` account (resolve with
`gh api user -q .login` during implementation; referred to as `<gh-user>` below).

## 4. Plugin manifest and marketplace

**`.claude-plugin/plugin.json`:**

```json
{
  "name": "anchor",
  "description": "Personal code review: deterministic CLI gathers diff/context/learnings; the active Claude session reasons over them.",
  "version": "0.2.0",
  "author": { "name": "Mike Jenkins" }
}
```

Plugins auto-discover `commands/`, `skills/`, and `hooks/hooks.json` — no
component paths needed in the manifest.

**Marketplace repo `<gh-user>/claude-plugins`** (new, public) contains only:

```
.claude-plugin/marketplace.json
README.md
```

`marketplace.json` lists one plugin: name `anchor`, source
`{ "source": "github", "repo": "<gh-user>/anchor" }`. The README documents the
two-command machine setup:

```
/plugin marketplace add <gh-user>/claude-plugins
/plugin install anchor@claude-plugins
```

Updates: bump versions in the anchor repo, push, then `/plugin update anchor`
on each machine (or rely on marketplace auto-refresh).

## 5. CLI bundling

- `esbuild` becomes a devDependency (version pinned by lockfile).
- `make bundle` runs esbuild over `bin/anchor.mjs`: `--bundle`,
  `--platform=node`, `--format=esm`, shebang banner, output `dist/anchor.mjs`.
  `js-yaml` and `minimatch` are inlined; the result runs on bare Node with no
  `node_modules`.
- `dist/anchor.mjs` is **committed**. It is a release artifact: regenerated by
  `make bundle` before every tagged release.
- Two integration tests guard it (§10): freshness (rebuild and diff against the
  committed file) and smoke (run the committed bundle in a fixture repo).
- Unit/integration/golden tests continue to run against **source**, not the
  bundle.

## 6. Skill changes (`skills/anchor/SKILL.md`)

- Frontmatter and all workflow content (review steps 1–8, safety guardrail,
  output format, init workflow) are unchanged from v0.1.0 except CLI
  invocation.
- The "The `anchor` CLI is on PATH" preamble is replaced. When Claude Code
  loads a skill it injects `Base directory for this skill: <path>`; for a
  plugin-installed skill that path is `<plugin-root>/skills/anchor`. New
  preamble instructs: derive the plugin root (two directory levels up from the
  skill base directory) and run every CLI call as
  `node "<plugin-root>/dist/anchor.mjs" <subcommand> [args]`.
- Every literal `anchor <sub>` invocation in the skill body is rewritten to
  that form.
- Dispatch table gains one row: `hook install|uninstall` → run the matching CLI
  subcommand in the current repo (used to manage the per-repo pre-push
  reminder).

## 7. Slash command changes (`commands/anchor.md`)

- Stops referencing `~/.claude/skills/anchor/SKILL.md` (that symlink will not
  exist). The `init`, `review`, `full`, and `--explain` bullets instead say:
  invoke the `anchor` skill (Skill tool) and follow the matching workflow.
- Pass-through subcommands (`diff`/`context`/`learn`/`status`/`doctor`, and new
  `hook`) also defer to the skill, which knows how to locate the bundled CLI.
- Frontmatter `argument-hint` gains `hook`.

## 8. Hooks

**PostToolUse push reminder** — registered declaratively in `hooks/hooks.json`:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command",
            "command": "\"${CLAUDE_PLUGIN_ROOT}/hooks/post-push-reminder.sh\"" }
        ]
      }
    ]
  }
}
```

Claude Code activates this automatically while the plugin is enabled; no
settings.json editing. The script itself (stdin pre-filter, authoritative
match, `ANCHOR_NO_REMIND=1` opt-out, always exit 0) is unchanged. The
settings-editing machinery from v0.1.0 (`lib/posttool-hook.mjs`,
`bin/install-posttool-hook.mjs`) is deleted.

**Git pre-push reminder** — moves from Makefile targets into the CLI so it
works from the plugin cache without a cloned repo:

- New `lib/hook-script.mjs` exports the pre-push script as a template string.
  It is byte-identical to the v0.1.0 `hooks/pre-push`, including the
  `# Anchor pre-push reminder` marker line (so uninstall recognizes hooks
  installed by v0.1.0's `make install-hook`).
- New CLI subcommand `anchor hook <install|uninstall>` operating on the current
  repo, JSON output by default like other subcommands:
  - `install`: error if not a git repo; error if `.git/hooks/pre-push` exists
    unless `--force`; creates `.git/hooks` if missing; writes the script,
    chmod +x.
  - `uninstall`: no hook → ok with notice; hook contains the anchor marker →
    remove; foreign hook → refuse with message, exit 1.
  - Exit codes and messages mirror the v0.1.0 make targets; `FORCE=1` env
    becomes the `--force` flag.

## 9. Doctor rework (`lib/doctor.mjs`)

Removed (symlink-era): skill symlink check, command symlink check, `~/bin`
PATH/symlink check.

Added:

- **bundle**: `dist/anchor.mjs` exists adjacent to the running script's
  package root (fail-level when running from a plugin install, since a missing
  bundle means a broken release).
- **plugin install** (warn-level): the running script resides under
  `~/.claude/plugins/cache/`; otherwise report "running from source checkout
  (dev mode)" as a warning, not a failure.

Kept: git present + major ≥ 2, inside-a-repo context check, gh available
(warn), config valid (warn), `CLAUDECODE=1` env (warn), node version. Exit
semantics unchanged (any fail-level check → exit 1).

## 10. Testing

- All existing unit/integration/golden suites stay green against source, minus
  the two deleted posttool-installer test files
  (`tests/unit/posttool-hook.test.mjs` only; the
  `posttool-hook-script.test.mjs` integration suite stays — the script still
  ships).
- **New** `tests/integration/bundle.test.mjs`: (a) freshness — run esbuild to a
  temp file with the same flags as `make bundle` and assert byte-equality with
  the committed `dist/anchor.mjs` (esbuild pinned by lockfile makes this
  deterministic); (b) smoke — execute the committed bundle (`doctor`, `diff`)
  in a fixture repo and assert valid JSON + exit codes.
- **New** `tests/integration/hook-subcommand.test.mjs`: ports ALL of the old
  `hooks.test.mjs` coverage, which is then deleted with the make targets.
  Script-behavior tests (reminder prints + exit 0, `ANCHOR_NO_REMIND=1`
  silence, real `git push` not blocked) now install via `anchor hook install`
  and exercise the script that `lib/hook-script.mjs` produced. Installer tests
  move to the subcommand (install, refuse existing without `--force`,
  `--force` overwrite, uninstall, foreign-hook refusal, non-repo error).
- `tests/manual/SMOKE.md`: install items rewritten for the plugin flow
  (marketplace add, plugin install, doctor, hook subcommand); review-workflow
  items unchanged.

## 11. Error handling

- Skill cannot determine the plugin root (no base-directory line, moved cache):
  the skill says so explicitly and suggests `/plugin update anchor` —
  it never guesses paths.
- Bundle missing/corrupt: `node` fails loudly; doctor's bundle check catches it.
- `hook install` in a worktree/submodule (`.git` is a file): same limitation as
  v0.1.0; error message states it plainly.
- Marketplace/plugin install failures are Claude Code's domain; Anchor adds no
  wrappers.

## 12. Migration (this machine, one-time)

1. Remove symlinks: `~/bin/anchor`, `~/.claude/skills/anchor` (directory
   containing the symlink), `~/.claude/commands/anchor.md`.
2. Remove the Anchor PostToolUse entry from `~/.claude/settings.json` (the
   pre-v0.1.0 backup at `settings.json.anchor-backup` is left untouched).
3. Create and push `<gh-user>/anchor` (public, full history + tags) and
   `<gh-user>/claude-plugins`.
4. `/plugin marketplace add <gh-user>/claude-plugins`, then
   `/plugin install anchor@claude-plugins`.
5. Verify: `anchor doctor` green via the skill, push reminder fires once (not
   twice), `/anchor review` works in a real repo.

Repos that installed the pre-push hook under v0.1.0 need nothing: script
content and marker are identical, and `anchor hook uninstall` recognizes them.

## 13. Versioning and release flow

- `plugin.json` and `package.json` versions move in lockstep; this release is
  **0.2.0**.
- Release: bump both versions → `make bundle` → full test suites + typecheck →
  update CHANGELOG → commit → tag `vX.Y.Z` → push with tags. Machines update
  via `/plugin update anchor`.
- Dev loop stays source-based (run `node bin/anchor.mjs` directly; tests hit
  source). To test plugin packaging locally before pushing, add the local
  marketplace clone by path (`/plugin marketplace add <path>`), install from
  it, then remove it.

## 14. Rollout

1. **Phase A — restructure:** manifest, move skill, hooks.json, delete
   settings-installer machinery, slim Makefile, doctor rework, `hook`
   subcommand, skill/command content updates.
2. **Phase B — bundle:** esbuild dep, `make bundle`, committed dist, bundle
   tests.
3. **Phase C — docs + release:** README/SMOKE/CHANGELOG updates, version bumps,
   tag v0.2.0.
4. **Phase D — publish + migrate:** create GitHub repos, push, marketplace
   repo, migrate this machine per §12, end-to-end verification.
